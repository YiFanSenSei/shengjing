# 个人间隔试用记录（待执行）

用途：验证“两次太频繁 → 出现建议 → 采纳或保留 → 重启 → 恢复”这一整套，目标用户是否看得懂、用得上。结果由 D 独立记录，C 不给自己打分。原始记录和联系方式留在仓库外，这里只放汇总。

## 准备

- 用 0.10.0 固定签名包；麦克风、通知权限已开；手表已配对。
- 居家、标准模式、三类关注、未暂停；手机放在桌上。
- 每位参与者单独一轮。先让对方自己操作，卡住再提示，并记下提示原话。

## 每人步骤

1. 开启监听，真实敲门两次，间隔至少 20 秒。
2. 第一条可先在手表确认，再在记录页点“声音认对了，但提醒太频繁”；第二条直接点同一项。检查出现建议，且实际间隔仍是 15 秒。
3. 问：这条建议在说什么？拉长后可能发生什么？记下原话，不替对方总结。
4. 选择“采用 60 秒”。回首页确认间隔；20 秒后再敲一次，观察第二次是否被挡；问是否接受这个代价。
5. 重启应用，确认间隔仍在；回记录页点“恢复 15 秒”。
6. 记下建议、采用、保留、恢复各自是否成功，以及卡住的地方。

## 判定

- 至少 3 位目标用户；朋友和听障/老年使用者分开统计。
- 3 人里至少 2 人能说清“拉长间隔会减少重复提醒，但可能漏掉下一位来客”，且恢复成功，才可以对外说“可用”。
- 不足 3 人，或多数人说不清，就写“未验证”，先改文案或门槛，不宣称有效。
- 只报人数、次数和原话，不把 3 人换算成百分比。

## 已知限制

- 学习场景是 60 秒起步，采纳后 120 秒；家门场景更明显。试用优先做居家，时间够再做学习。
- 建议要两次有效“太频繁”反馈才出现；模拟提醒、被系统阻止、已标“认错了”的记录不计入。
- 这条链路只证明偏好交互，不证明识别率或手表送达；那两项由 A、D 的现场测试负责。
