# 阶段验收计划

## 已验证的基础链路

2026-11-16，用户确认手机与 Watch X2 的三类模拟提醒、振动、确认及误报回传成功，0.1.1 短时锁屏模拟提醒成功。三类振动有细微节奏差别，尚未做盲辨测试。真实声音识别与长期后台监听不计为通过。

## 当前阶段交付：0.2.0

目标是让真实识别失败可定位，并改善监听启动、停止与重新启动的稳定性。交付内容包括采集电平、全部类别中最高分类、三类目标分数与峰值、策略原因、异常阶段提示、旧会话回调隔离，以及固定开发签名安装包。保持原有提醒阈值；这一阶段不承诺识别准确率改善。

自动检查完成后再集中进行以下真机测试，不需要一直连接电脑：

| 项目 | 操作与验收依据 | 状态 |
|---|---|---|
| 覆盖升级 | 使用固定签名包覆盖 0.1.1；确认版本、通知权限和同步设置保留 | 待测 |
| 采集与诊断 | 开始监听，打开诊断；有效窗口数持续增长；安静与敲门时电平、分类分数变化 | 待测 |
| 实际敲门 | 在同一位置敲真实房门 5 次，每次隔至少 15 秒；记录提醒数和敲门峰值，不用敲桌代替 | 待测 |
| 负样本 | 安静、谈话、敲桌分别观察；记录是否出现不应有的提醒 | 待测 |
| 类别与暂停 | 关闭类别/开启暂停时，不应发出该真实提醒；诊断仍可查看 | 待测 |
| 停止与重启 | 连续开始/停止 5 次；停止后麦克风使用指示结束，重启后窗口数重新增长 | 待测 |
| 系统麦克风关闭 | 关闭系统麦克风访问，观察全零音频/采集停滞/权限错误提示；恢复后停止再开始 | 待测 |
| 基础链路回归 | 模拟提醒、手表振动、确认与误报回传、10 秒锁屏通知 | 待测 |
| 取消延迟提醒 | 安排延迟提醒后立即取消，等待超过 10 秒，不能出现新的模拟敲门 | 待测 |

只记录合成/公开测试音、类别、分数、计数和设备版本；不提交真实录音、账号、序列号或包含个人通知的截图。5 次事件仅用于故障排查，不作为准确率报告。

## 后续阶段

1. 采集可重复的真实场景证据，区分识别类别偏差、阈值不合适与环境噪声，再调参；以独立评测集报告召回、误报和延迟。
2. 完成设置持久化、会话内事件记录与清除、通知权限引导及可访问性界面，统一做交互验收。
3. 专项验证锁屏 2 分钟/10 分钟、系统省电、连接断开与重连，再考虑是否需要独立手表应用。短时唤醒锁测试不能替代此项。

每个阶段交付一个说明清晰的测试包与验收清单，集中收集反馈；日常开发优先使用自动检查。
