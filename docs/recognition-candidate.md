# 0.3.0：敲门与闹钟增强模式候选

本次真正修改提醒判定：增强模式将敲门、闹钟阈值从 0.60 降到 0.40；门铃仍为 0.60。默认关闭，用户打开“敲门 / 闹钟增强模式（试验）”后生效。暂停、类别开关、连续事件去重和 15 秒冷却仍保留。切换模式不会清空冷却，重启进程后回到标准模式。

## 同一批缓存分数的回放比较

| 干净音频 | 标准 0.60 | 候选 0.40 |
|---|---|---|
| 敲门正片段检出 | 27/40（67.5%） | 35/40（87.5%） |
| 敲门标签负片段触发 | 6/1960 | 7/1960 |
| 闹钟正片段检出 | 27/40（67.5%） | 32/40（80.0%） |
| 闹钟标签负片段触发 | 0/1960 | 0/1960 |

选择依据：0.50 已改善检出，0.40 在相同敲门负片段触发数下增加正片段检出；进一步降到 0.30 时，敲门检出仍为 35/40，但负片段触发增至 9 条，闹钟开始出现负片段触发。因此选择 0.40 作为可切换候选，不宣称全局最优。

这组音频已用于查看并选择阈值，上表是开发集回放，不是独立验证或准确率保证。数据为片段标签；疑似误报须听检，且模型预训练来源重叠未核查。手机实际窗口时序、去重策略和麦克风条件与离线峰值回放不同。

噪声结果显示局限：客厅/厨房 0 dB 敲门仍为 0/8；厨房 20 dB 从 3/8 到 5/8，办公室 20 dB 从 6/8 到 7/8，同时新增一条标签负片段触发。仅降低阈值不能解决强噪声下模型分数过低的问题。详细网格与各条件结果见 recognition-candidate-summary.json，其中 0.40 的门铃列仅为诊断回放，不用于应用，应用门铃仍为 0.60。

## 下一次集中真机验收

安装固定签名 0.3.0 后，对真实房门、闹钟分别比较标准/增强模式。每次独立触发间隔至少 15 秒；交替模式、重复多次，记录触发数、分数与环境。另测脚步、敲桌、门吱呀声等负例及持续背景干扰，检查增强是否增加打扰。不要只挑增强成功的样本。

本次无需立即连接手机；先交付阶段包，再集中验收。还需新增独立自采保留集，才能判断候选方案是否在未参与调参的真实场景中改善。强噪声问题后续应研究专用分类器/特征与训练数据扩充，不能用界面演示或更低阈值替代证据。

复现：在评测虚拟环境运行 `python evaluation/compare_thresholds.py <本地 clips.jsonl> <输出 JSON>`。无需重新下载或重新推理原有数据，不改写基线结果。
