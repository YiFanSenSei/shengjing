# 场景与偏好回放（0.10.0）

2026-11-28。只把固定分数和固定时间喂给提醒规则，不读音频、不连手机、不打开麦克风。它说明规则会怎么判，不代替真机现场证据。

同一串事件：第 0 秒第一位来客，第 1 秒同一串敲击，第 20 秒同一位来客再敲（不希望再提醒），第 40 秒第二位来客（希望提醒），第 42 秒门铃，第 45 秒闹钟，第 61 秒第三位来客（希望提醒），第 85 秒桌面轻响 0.35。所有声音都用 0.80 分，只有桌面轻响用 0.35，标准模式判为低分。

|---:|---|---|---|---|---|
| 0 | 第一位来客敲门 | 提醒 | 提醒 | 提醒 | 提醒 |
| 1 | 同一串敲击 | 同串 | 同串 | 同串 | 同串 |
| 20 | 同一位来客再敲 | 提醒 | 冷却 | 冷却 | 冷却 |
| 40 | 第二位来客敲门 | 提醒 | 冷却 | 冷却 | 冷却 |

| 45 | 闹钟 | 提醒 | 提醒 | 提醒 | 提醒 |

|---|---:|---:|---|
| 居家默认 | 5/5 | 1 次（第 20 秒同一来客） | 0 |
| 学习默认 | 4/5 | 0 | 1 次（第 40 秒第二位来客） |
| 居家采纳 60 秒 | 4/5 | 0 | 1 次（第 40 秒第二位来客） |
| 学习采纳 120 秒 | 3/5 | 0 | 2 次（第 40、61 秒） |

## 增强模式只改阈值

| 事件 | 标准 0.60 | 增强：敲门/闹钟 0.40 |
|---|---|---|
| 第 0 秒敲门 0.45 | 低分 | 提醒 |
| 第 1 秒同一串 0.45 | 低分 | 同串 |
| 第 42 秒门铃 0.45 | 低分 | 低分（门铃仍为 0.60） |

## 怎么读

- 同一串声音，换场景、换偏好，结果就变了。门铃和闹钟不受敲门偏好影响。
- 居家默认会多提醒一次同一来客；学习默认挡掉第二位来客（第 40 秒）；采纳 60 秒后居家也会挡掉第二位；学习采纳 120 秒连第三位（第 61 秒）也挡掉。
- 第 40 秒是“第二位来客”，属于用户需要的新事件。它被挡掉就是“少打扰”的代价，演示时要主动说，不能只展示少提醒。
- 回放只覆盖规则，不证明识别、通知和手表送达。真实现场仍由 D 用双文件计分；原因记录见[提醒规则约定](policy-contract.md)。

## 复现

需要 JDK 17 或更高版本。用 Gradle：

```powershell
python scripts/bootstrap.py --gradle
tmp\tools\gradle-8.11.1\bin\gradle.bat :engine:policyTest :engine:policyReplay
```

没有 Gradle 时可直接编译：

```powershell
javac -encoding UTF-8 -d tmp/engine-classes agent/engine/src/main/java/org/shengjing/core/*.java agent/engine/src/test/java/org/shengjing/core/PolicyReplay.java
java -cp tmp/engine-classes org.shengjing.core.PolicyReplay
```

程序会核对每个时间点的提醒和原因；和表不一致就报错退出。`PolicyTest` 另覆盖 60/120 秒边界、偏好不跨场景、闹钟不能采纳、两位来客和场景切换。

## 限制

- 分数和时间是脚本设定的，不代表真实识别率。
- 偏好回放直接采用 60/120 秒；真实应用要先收到两次“太频繁”反馈才会建议。
- 现场仍需要 A 导出、D 独立观察；没有原因记录时，漏提醒只能标“不可归因”。
