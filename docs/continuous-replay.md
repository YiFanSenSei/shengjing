# 连续背景与门铃插入回放 · 2026-11-27

声境 0.9.0 基线取自合并提交 ce0b386。D 在电脑端使用手机同款 YAMNet 模型和仓库中的 Java 提醒策略，将相同分数流分别交给居家、学习场景的标准与增强模式。四种设置使用同一批录音。

## 实测结果

| 环境 | 原始连续背景，任一设置的提醒数 | 标准模式门铃命中／插入 | 增强模式门铃命中／插入 | 增强模式额外提醒 |
|---|---:|---:|---:|---|
| 客厅 | 0 | 1/4 | 1/4 | 0 |
| 办公室 | 0 | 2/4 | 2/4 | 1 次闹钟 |
| 厨房 | 0 | 1/4 | 1/4 | 1 次闹钟 |

三个原始背景各 300.004 秒，合计约 15 分钟、3,591 个推理窗口。计时不因重复比较四种设置而增加。仅凭这三段无触发录音，还不能估计宿舍真实误报率。

插入测试固定使用四段已在前期分析过的公开门铃。每种背景再回放一条 120 秒混音，共 1,431 个窗口。按当前居家和学习规则，本轮各场景的结果相同。电子门铃在三个背景均命中，经典双音仅在办公室命中，简易双音和老式响铃均未产生门铃提醒。两档模式各命中 4/12 个插入条件，原始门铃声源只有四个。该集合用于回归，不能作为四人团队新收集的盲测样本。

**可复现的混淆案例。** 老式响铃在第 70 秒插入。办公室和厨房的增强模式均在第 71.5 秒产生闹钟提醒；相同位置的原始背景没有提醒，标准模式也没有闹钟提醒。B 可对照响铃与闹钟的输出；C 可用相同分数流评估候选策略。D 应另留未参与开发的真实门铃和闹钟检验改动收益。

## 实验口径与复现

- 使用 DEMAND 的客厅、办公室、厨房原文件第一个声道和原始幅度。手机按 16 kHz 采样，每 4,000 点推进一次；首次收满 16,000 点后取最近 15,600 点输入，之后每 250 毫秒产生结果。时间戳取窗口结束时刻。每条连续录音从新的策略状态开始。
- 取同一背景前 120 秒，分别在第 10、40、70、100 秒插入经典双音、简易双音、老式响铃和电子门铃。按各自录音全长 RMS 将信噪比设为 10 dB，保留原背景，若发生削波风险则对整段共同缩放。将对应类别在该片段区间至结束后两秒内出现的首次提醒计为一次命中。插入时间指文件起点，可能含前导静音。
- 这些时刻来自离线音频时间轴，手机采集、系统通知和腕上送达均需真机观察。原始数据、许可和文件级校验继承自[公开门铃回放](doorbell-public-probe.md)与[公开数据评测环境](../evaluation/README.md)。数值可查[逐环境、逐模式结果](continuous-replay.json)。

使用 JDK 17、Python 3.12、锁定的音频评测依赖及 soundfile 0.13.1。背景压缩包放在 downloads 根目录，四个原始 Ogg 放在其 commons-doorbells 子目录。从仓库根目录运行：

```powershell
python evaluation/continuous_background.py <downloads目录> <yamnet.tflite> <结果.json>
```
