# 0.4.0 集中验收前的电脑端结果

## 场景策略

测试直接调用应用使用的 `Policy.observe`，将同样的八条候选分数按时间先后分别送入全新的居家、学习策略。模式为标准，三个类别均开启。回放中的来客身份和用户是否希望被提醒由测试脚本预设；手机端输入只有类别、分数和时间。

| 输入 | 居家 | 学习 |
|---|---|---|
| 0 秒首次敲门、1 秒同一串敲击 | 首次提醒，连续敲击合并 | 同左 |
| 20 秒同一人再敲，预设不需要提醒 | 额外提醒一次 | 冷却中 |
| 40 秒另一位来客，预设需要提醒 | 提醒 | 冷却中，漏掉一次需要的提醒 |
| 42 秒门铃、45 秒闹钟、61 秒再次敲门 | 各提醒一次 | 各提醒一次 |
| 85 秒敲桌，输入敲门分数 0.35 | 低于阈值 | 低于阈值 |

这个例子里，居家覆盖预设需要的 5/5 次，另有 1 次打扰；学习覆盖 4/5 次，额外打扰为 0。回放验证了策略行为。它没有测量声学识别率、真实用户偏好或手表送达。后续用户试用应区分「识别错误」「声音正确但不想提醒」及「想收到却没提醒」。第三类需要观察者独立记录实际事件，应用历史本身看不到漏掉的事件。

在仓库根目录用 JDK 17 复现。程序会核对 16 个决策及对应提醒状态，出现差异时退出并标明时间点。

```sh
javac -encoding UTF-8 -d tmp/engine-classes agent/engine/src/main/java/org/shengjing/core/Policy.java evaluation/SceneReplay.java
java "-Dfile.encoding=UTF-8" -cp tmp/engine-classes SceneReplay
```

## 门铃数据盘点

FSD50K 本地 ground truth 中，144 条不同片段同时符合精确标签 Doorbell 和词表 ID `/m/03wwcy`。官方 train、val、eval 分别为 90、17、37 条。标签可与其他声音并存。此处只建立元数据索引；尚未对这些音频推理。使用音频前逐条核对许可和用途，保留官方划分，另留真实房间与真实门铃作为现场验收集。

```sh
python evaluation/index_doorbells.py <FSD50K.ground_truth目录> <本地输出JSON路径>
```
