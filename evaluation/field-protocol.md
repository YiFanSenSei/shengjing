# D 端现场验收单

适用于 Find X8 Pro、Watch X2 和声境 0.9.0。每次测试前写下 APK 版本、场景、增强开关、关注类别、提醒间隔、手机位置与锁屏条件。比较两个版本时固定这些条件，轮换版本先后顺序。声源、房间或采集场次参与过调参的材料归入开发组；保留组结果一旦用于改参数，下轮另留验收组。

## 半小时设备验收

1. A 操作设备，D 用同一只秒表记录相对时间。先在手机和手表核对连接，做好模拟提醒后再开始正式计时。以居家、标准模式、三类关注、关闭暂停为本轮配置。启动监听、开始新一轮演示，锁屏。
2. D 独立记下实际发生的声音、开始秒和结束秒。建议第 2、10、20 分钟分别触发真实敲门、门铃和闹钟，各补一次不同顺序的复测；相邻同类声音间隔超过已配置的冷却时间。最后一次触发后留足观察时间。缺少真实设备时记为未测；用扬声器播放的用例另建回放场次。
3. 观察端记录手机事件时间及类别、通知请求状态、腕上是否出现、观察到的秒数。同类连续事件用时间及手机记录逐一对应。没有看表或无法配对时填 unknown。确认没收到且观察完整时才填 missed。可用另一台设备辅助计时；无法可靠取得手机事件时间时保留为定性记录，不用解锁时间或手点反馈时间替代。
4. 不中途暂停秒表。观察中断时结束该场，另开连续场次；两次有效时段分别计算。背景时段如有真实目标声也要标注。统计全程覆盖，单独测试纯背景时可留空 truth。
5. 停止监听并保存演示摘要。由 A 核对应用诊断，D 核对人工真值。手机汇总仅用于核对漏记或重复记录，单独的“本轮腕上看到了”不能补成多条到达记录。

## 录入与计算

把 [合成填写例](field-example.json) 复制到仓库外，移除示例数据再填写。真实场次设置 source 为 field。命令在仓库根目录运行：

```powershell
python -m evaluation.field_report <本地场次.json>
```

| 字段 | 记录方式 |
|---|---|
| duration_s、truth | 有效连续观察秒数；每次真实事件的 label、onset_s、offset_s。类别为 knock、doorbell、alarm。 |
| phone | 每次真实识别记录填 label、at_s、simulated=false；系统通知状态为 requested、blocked 或 failed。 |
| wrist、wrist_s | 对已请求通知填 seen、missed 或 unknown。看到但未记准时间可省略 wrist_s，此时只算到达，不算延迟。被阻止或发送失败填 unknown，不进入腕上送达分母。 |

程序按时间顺序一对一匹配同类事件，从事件开始到结束后两秒内有效。输出按类手机命中数、召回、每小时额外提醒、重复提醒和延迟。腕上另报已观察请求中的到达比例及观察缺失数；已核实端到端命中以全部真值为分母。延迟仅对有对应真值且实际看见腕上提醒的样本计算。单次样本很少时优先列原始分子和分母。不要平均不同场次的百分比；按相同条件累加计数和有效观察时长后计算。

## 首次使用走查

每位自愿参与者独立完成四个任务：开启监听、收到提醒后判断声音、在腕上或手机确认并查到相应记录、停止监听。D 逐任务记“独立完成／经提示完成／未完成”、用时和卡住的操作；先让对方自己尝试，给提示时记下原话中的操作要点。结束后询问哪种提醒能分辨、哪条文字难理解、哪些提醒太频繁。朋友流程走查与听障或听力下降使用者体验分组汇总，未经同意不记录身份、诊断、联系方式或录音。
