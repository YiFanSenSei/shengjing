# A、D 同场验收 · 声境 0.10.0

**准备。** A 在手机上打开「现场演示与锁屏核对」，开启监听。D 在电脑上用 Chrome 或 Edge 打开同目录的 [离线观察页](field-observer.html)，保持电脑唤醒。两人先约定用哪种真实声音、场景和增强配置；正式观察中保持配置固定。比较版本时另外记下 APK 版本、设备、房间与距离。

| 时机 | A 操作手机 | D 独立观察 |
|---|---|---|
| 起点 | 点「开始新一轮」，读出 8 位场次编号 | 同时点「开始计时」，填入编号。人工同步和点按都有误差，不据此作毫秒级性能声明。 |
| 现场 | 可以锁屏；真实识别提醒自动记录，模拟事件单独计数 | 每次声音开始和结束分别点同类按钮；在腕上看到提醒时点「刚在腕上看到提醒」。无法同时观察时安排另一位队员协助。 |
| 结束 | 最后一次触发后留足反应时间，先点「结束本轮并保存摘要」，再点「保存本轮手机事件文件」，选择本机位置 | A 结束后再点「结束观察」。先完成真实事件记录，再载入 A 的 JSON。按序号、类别、时间手动配对腕上观察；无法确定的保留未知。 |
| 报告 | 把手机文件交给 D | 勾选完整核对并保存观察文件。缺失观察时保留草稿，用于定性复盘。 |

在含有 evaluation 文件夹的目录运行（Python 3.11+，标准库即可）：

```powershell
python -m evaluation.field_handoff 手机文件.json 观察文件.json
```

若使用生成的演练数据，加 `--practice`。计分含逐类召回、额外提醒／小时、腕上到达及缺失、端到端 P50/P95 和对应样本数。没有可用时间戳时延迟为 null。场次编号不一致、观察不完整、缺失引用或早于手机事件的腕上时间都会阻止计分。只有 A 文件时保留作设备诊断。

手机时间取自应用处理提醒时的单调时钟，以本轮开始为零点，包括锁屏经过的时间。导出只含场次随机编号、相对时间、配置与事件状态；超出 100 条真实提醒、进程中断或未手动收尾时不导出明细。下一轮替换应用内上一次明细，清空历史同时删除应用内明细。已保存到其他位置的文件需自行管理。

观察页在内存中运行，刷新会丢失未保存的记录。「保存观察文件」可下载阶段草稿。正式计分只用完整、同一时间基准的场次。个别观察时刻对不齐时可填“已看到，时刻不详”；整轮起点不可靠或中途未能观察真实声音时，留作定性材料。
